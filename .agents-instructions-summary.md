## Structure and Content

The instructions follow the documented template with these sections:

### 1. **Orientation** 
Explains that this is a reference implementation for CRTC telecommunications regulations (2026-78) using TypeScript/Node.js, MongoDB, and BMAD workflow framework. Clarifies this is not legal advice.

### 2. **Policy**
Four key organizational policies:
- Reference implementation disclaimer (not legal/compliance guidance)
- BMAD skills are the primary workflow
- Customizations go in `_bmad/custom/` to survive reinstalls
- Prototype implementations require security hardening for production

### 3. **Where Things Are**
Entry points and pointers for agents to find:
- Planning/analysis output in `_bmad-output/`
- BMAD skill library in `.agents/skills/`
- Five custom agents (Mary, John, Sally, Winston, Amelia) in `.github/agents/`
- Configuration in `_bmad/config.toml`
- Prototype app in `prototype/enterprise-plan-rules-store/`
- Original regulatory source in `source/`

### 4. **Running and Verifying**
Four commands/workflows agents need:
- **BMAD workflow**: How to invoke agents by name or skill name
- **Config resolution**: The exact `uv run` command with output format
- **Prototype stack setup**: Node.js installation, MongoDB requirements, dev server startup
- **Testing**: Unit tests and build verification for prototype

### 5. **Conventions That Differ from Defaults**
Four key deviations from standard practices:
- Document output goes to `_bmad-output/` with date/ID naming
- TOML and Python configuration (not JSON)
- Agent naming conventions (names in conversation, kebab-case skill names)
- API proxy routing (port 4000)

### 6. **Known Pitfalls**
Six pitfalls captured from project structure and git history:
1. Config not auto-resolved (requires manual script run)
2. Output paths controlled by config (not hardcoded)
3. MongoDB constraints on rule versions
4. API v0 status (no versioning yet)
5. Regulatory analysis scope (public sources only)
6. Git history structure (single import commit)

## Why These Specific Instructions

Each instruction was selected using the **best-practices criteria**:

✅ **Admitted** (high-cost rediscovery):
- Five custom agent names and their roles — agents must know who to invoke
- Config resolution workflow — setup mistake would waste sessions troubleshooting
- Prototype environment requirements — obvious guess (npm, node) lacks critical MongoDB and docker-compose requirements
- Directory structure — planning/implementation artifact split is non-obvious
- BMAD skill customization path — prevents agents overwriting their own instructions

✅ **Excluded** (available elsewhere):
- Stack list (TypeScript, Node, MongoDB) — already in package.json and README
- Directory tree — `view` command shows structure
- Pasted code/changelog — already in git history
- Skill catalog listing — `bmad-help` SKILL.md serves this

✅ **Pitfalls grounded in evidence**:
- Config auto-resolution issue — found in `bmad-help` and `bmad-project-context` SKILLs (requires manual script)
- MongoDB unique revision constraint — documented in prototype README
- Prototype API v0 status — no versioning in endpoints or config
- Git single-import structure — `git log` output shows import at `9248e2d`
